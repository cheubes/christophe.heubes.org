# Data model

## Overview

The site holds two content families, each with its own data format and its own page generation mechanism (see "Architecture" in `technical-specifications.md`):

- **Photo gallery** (scuba diving, street art, wanderings): a generic screen (see `screens/gallery.md`), one data entry per photo.
- **Technical drawing**: a dedicated two-view screen (see `screens/technical-drawing.md`), one data entry per drawing, each drawing represented by two images (original and 2020 reproduction).

Both families share the same content file model: each page exists as two Markdown files, one per language, linked by a shared `ref` field (see "General conventions" below).

## Photo gallery

### Data (`_data/<gallery>.yml`)

One entry per photo, in the order it must appear in the grid (see `screens/gallery.md`):

```yaml
- file: 2026-07-merou-estartit.jpg
  title-fr: "Mérou, l'Estartit."
  title-en: "Grouper, l'Estartit."
```

| Field | Description |
|---|---|
| `file` | Image file name in `content/<gallery>/`, with its extension |
| `title-fr` | Caption displayed in French (lightbox, `alt`, JSON-LD) |
| `title-en` | Caption displayed in English |

Three data files, one per gallery: `_data/under-water.yml`, `_data/street-art.yml`, `_data/deambulations.yml`. The file name (without extension) is the gallery slug, reused as `page.gallery` (see below) and as the name of the `content/<gallery>/` folder.

### Images

For each entry `file: <slug>.<ext>`, two image files in `content/<gallery>/`:

| File | Role | Generated by |
|---|---|---|
| `<slug>.<ext>` | Original photo, displayed in the full-screen lightbox | Added manually to the repository |
| `<slug>-thumb.<ext>` | Thumbnail used in the grid (see `screens/gallery.md`) | `scripts/generate_gallery_thumbnails.rb`, see `technical-specifications.md` |

Each `content/<gallery>/` folder also contains a `gallery-band-bg.jpg` file, the background image of that section's cinematic band on the home page (see `screens/home.md`), with no matching entry in the `.yml`: it is not a gallery photo but an interface image. Observed dimensions (`under-water/gallery-band-bg.jpg`): 2400 × 800 px (3:1 ratio); to be reproduced for the other galleries.

### Gallery page (front matter)

One Markdown file per language at the root of `content/` (`content/<gallery>.md` for French, `content/<gallery>-en.md` for English), which generates the grid view of that gallery:

```yaml
---
sitemap:
  priority: 0.7
  lastmod: 2026-08-12

layout: gallery
gallery: under-water
ref: under-water
permalink: /under-water/

lang: fr
flag: 🇫🇷

title: Christophe Heubès - Photos sous-marines
description: Christophe Heubès - Photos sous-marines
h1: Photos sous-marines
icon: fa-water
introduction: Sous la surface, un autre monde. Voici quelques images remontées de mes plongées.
---
```

| Field | Role |
|---|---|
| `sitemap.priority` | Present in the front matter but not read by the site's current `sitemap.xml` (see "SEO" in `technical-specifications.md`); kept for information only |
| `sitemap.lastmod` | Last content modification date, used by `sitemap.xml` |
| `layout` | Always `gallery` for the three photo galleries (see `screens/gallery.md`) |
| `gallery` | Gallery slug, key into `site.data[page.gallery]` |
| `ref` | Identifier shared between the two languages of this page, see "General conventions" |
| `permalink` | `/<gallery>/` in French, `/en/<gallery>/` in English (see "Multilingual" in `functional-specifications.md`) |
| `icon` | Font Awesome class (see "Iconography" in `style-guide.md`) |
| `introduction` | Text displayed below the grid title and reused as the description in the home page cinematic band |

### Individual photo pages (generated)

For each photo of `_data/<gallery>.yml`, a page is generated at `/<gallery>/<slug>/` (and its equivalent `/en/<gallery>/<slug>/`): same content as the grid, with the lightbox opened directly on that photo (see "Permalinks" in `technical-specifications.md`). These pages do not exist as source files: they are produced in memory at build time by `_plugins/gallery_photo_pages.rb` (see `technical-specifications.md`), from the gallery page of the matching language, whose whole front matter they inherit, plus the following fields:

| Field | Value |
|---|---|
| `ref` | `<gallery>-<slug>` |
| `photo_slug` | `<slug>` |
| `photo_caption` | The entry's `title-fr` or `title-en`, depending on the base page's language |
| `title`, `description` | `Christophe Heubès - <photo_caption>` |
| `image` | `/content/<gallery>/<file>`, used for this page's Open Graph and JSON-LD |

## Technical drawing

### Data (`_data/technical-drawing.yml`)

One entry per drawing, in the order it must appear in the list (see `screens/technical-drawing.md`):

```yaml
- id: etude-came
  org-year: 1941
  fr-title: Etude d'une came - Schéma et diagramme - Détails de la came et du levier
  en-title: Study of a cam - Diagram and schematic - Details of the cam and lever
```

| Field | Description |
|---|---|
| `id` | Drawing slug, reused for the image file names and the detail page URL |
| `org-year` | Year the original drawing was made (1939 to 1942), displayed as a label of the before/after comparator |
| `fr-title` | Drawing title in French |
| `en-title` | Drawing title in English |

### Images

For each entry `id: <id>`, two image files in `content/technical-drawing/`:

| File | Role |
|---|---|
| `<id>-org.jpg` | Original ink-on-tracing-paper drawing, made by Claude Heubès between 1939 and 1942 |
| `<id>-2020.jpg` | Digital reproduction made by Christophe Heubès in 2020 |

The two images of a same drawing have nearly identical dimensions (e.g. 2048 × 1536 px and 2048 × 1537 px for `etude-came`), a prerequisite for the before/after comparator to align properly (see "Before/after comparator" in `style-guide.md`). As for the photo galleries, `content/technical-drawing/gallery-band-bg.jpg` is the background image of the home page cinematic band, with no entry in the `.yml`.

### List page (front matter)

One file per language at the root of `content/` (`content/technical-drawing.md`, `content/technical-drawing-en.md`), same structure as the gallery pages above (`layout: technical-drawing`, `ref: technical-drawing`, `permalink: /technical-drawing/` or `/en/technical-drawing/`, `icon: fa-compass-drafting`), with an `introduction` that may contain raw HTML (link to the ENSAM Wikipedia page in the text).

### Detail pages

Unlike the individual photo pages of the galleries, the technical drawing detail pages are **real Markdown files**, committed in `content/technical-drawing/`: `<id>.md` (French) and `<id>-en.md` (English). They are not generated at build time, but by the maintenance script `scripts/generate_technical_drawing_pages.rb` (see `technical-specifications.md`), to be run after any change to `_data/technical-drawing.yml` and then committed.

```yaml
---
sitemap:
  lastmod: 2026-08-04

layout: technical-drawing-detail
ref: technical-drawing-attelage-pour-crochet-de-traction
permalink: /technical-drawing/attelage-pour-crochet-de-traction/

lang: fr
flag: 🇫🇷

title: Attelage pour crochet de traction - Christophe Heubès
description: Attelage pour crochet de traction
image: /content/technical-drawing/attelage-pour-crochet-de-traction-2020.jpg

drawing-id: attelage-pour-crochet-de-traction
drawing-title: Attelage pour crochet de traction
---
```

| Field | Role |
|---|---|
| `ref` | `technical-drawing-<id>`, unique per drawing, shared between the two languages |
| `drawing-id` | `<id>`, key to the two image files and to the `_data/technical-drawing.yml` entry |
| `drawing-title` | Drawing title in the page language (copied from `fr-title`/`en-title`) |

## Image metadata

Each content image (gallery photo, its thumbnail, the two images of a technical drawing) carries the site's author and license (CC0 1.0 public domain dedication, see `LICENSE`) in the file itself, as EXIF, IPTC and XMP, in addition to the page's JSON-LD (see "SEO" in `technical-specifications.md`): this metadata follows the image when it is downloaded or indexed on its own. Interface images (`gallery-band-bg.jpg`, band backgrounds in `content/`, `assets/img/`) are not concerned.

### Common fields

| Field | Value |
|---|---|
| EXIF `Copyright` | `CC0 1.0` |
| IPTC `CodedCharacterSet` | `UTF8`, always required (the author's name contains an accent); without it, readers assume Latin-1 and display `Heubès` or `Œuvre` corrupted |
| IPTC `By-line`, XMP `dc:creator`, XMP `photoshop:Credit` | `Christophe Heubès` |
| IPTC `CopyrightNotice` | `Christophe Heubès - CC0 1.0` (same value as `copyrightNotice` in the JSON-LD) |
| XMP `dc:rights` | `Christophe Heubès - CC0 1.0` |
| XMP `xmpRights:Marked` | `False`: in XMP, `False` means public domain, which is what a CC0 dedication is (`True` would mean rights-managed) |
| XMP `xmpRights:UsageTerms` | `CC0 1.0` |
| XMP `xmpRights:WebStatement` | `https://creativecommons.org/publicdomain/zero/1.0/deed.fr` |

### Family-specific fields

| Field | Gallery photo | Technical drawing |
|---|---|---|
| IPTC `Caption-Abstract`, XMP `dc:description` | The entry's `title-fr` | The entry's `fr-title` |
| XMP `dc:title` | Free short title, without a final period (not derived from the `.yml`) | `fr-title` |
| IPTC `ObjectName` | Absent | `fr-title`, shortened at a readable break if it exceeds 64 bytes (IPTC field limit) |
| EXIF `Artist` | Absent | `Christophe Heubès` |
| XMP `photoshop:Source` | `christophe.heubes.org` | `Dessin original de Claude Heubès, ENSAM, <org-year>.` for `-org.jpg`, `Reproduction numérique 2020, d'après le dessin original de Claude Heubès, ENSAM, <org-year>.` for `-2020.jpg` |

Thumbnails carry exactly the metadata of their original, copied by `scripts/generate_gallery_thumbnails.rb` (see `technical-specifications.md`).

### Writing rules

- Write metadata with exiftool, writing IPTC and XMP in the same command so they stay identical.
- Do not fill `photoshop:AuthorsPosition` nor its IPTC equivalent `By-lineTitle`: this field holds the author's job title, not the image title.
- Declare `CodedCharacterSet=UTF8` on the first IPTC write. Adding it afterwards to a file that lacks it makes exiftool re-encode the existing IPTC texts as Windows-1252: these fields must then be rewritten (for example from their XMP equivalents).
- After any IPTC change to a file that went through Photoshop, the `Photoshop:IPTCDigest` field must match the new content (`-Photoshop:IPTCDigest=new`), otherwise readers following the MWG guidelines consider IPTC and XMP as potentially out of sync.

## Home page (front matter)

`index.md` (French, `permalink: /`) and `index-en.md` (English, `permalink: /en/`), `layout: index`, `ref: home`. In addition to the common fields (`lang`, `flag`, `title`, `description`), fields specific to the home page:

| Field | Role |
|---|---|
| `h1` | Name displayed in the hero |
| `about-s-t` | Text of the cinematic band to `samettof.org` (see "Sister sites" in `functional-specifications.md`) |
| `about-dataviz` | Text of the cinematic band to `dataviz.heubes.io` |
| `about-social-graphs` | Text of the cinematic band to `social-graphs.heubes.io` |

## 404 page

`404.md`, `layout: 404`, `ref: 404`, `permalink: /404.html`, `sitemap.exclude: 'yes'`. Unlike the other pages of the site, there is only **one 404 page** for both languages (`flag: 🇫🇷 🇬🇧`, `lang: fr`): its `message` field is a fixed text ("Page not found"), not localized according to the requested URL's prefix (see "Multilingual" in `functional-specifications.md`).

## General conventions

- **Slugs**: lowercase ASCII and hyphens (kebab-case), e.g. `under-water`, `attelage-pour-crochet-de-traction`.
- **`ref` shared by the two languages of a same page**: this is the mechanism linking the two language versions of a page (used by the footer language switcher, the `hreflang` alternates in `<head>`, and `sitemap.xml`, see `technical-specifications.md`). Two pages documenting the same content in both languages must carry the same `ref`; two pages with different content must never share a `ref`.
- **Added content exists in both languages**: an entry of `_data/<gallery>.yml` always carries `title-fr` and `title-en` in the same entry (no separate file per language); a technical drawing always generates its two detail pages (`<id>.md` and `<id>-en.md`) through the generation script. In practice, there is therefore no content published in a single language (see "Multilingual" in `functional-specifications.md`).
- **No validation script**: unlike other projects by the author, this site has no script automatically checking data consistency (slug uniqueness, presence of both language files, match between `_data/technical-drawing.yml` and the generated pages...). These rules are followed by convention, not mechanically checked.
